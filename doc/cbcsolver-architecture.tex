\section*{What is \texttt{CbcSolver}?}
\ghh{90}{\texttt{CbcSolver}} is the top-level driver class for the Cbc MIP solver executable and library
entry point, encapsulating the entire solve pipeline --- parameter initialization, command-queue
parsing, LP relaxation solves, preprocessing, cut/heuristic configuration, branch-and-bound search,
post-processing, and result reporting --- that used to live in the free functions \texttt{CbcMain0}/\texttt{CbcMain1},
now thin backward-compatible wrappers delegating to \ghc{3041}{\texttt{initialize()}} and \ghc{10320}{\texttt{run()}}.

Historically this logic was not even a class method: it lived in the free function \texttt{CbcMain1}
(paired with the smaller \texttt{CbcMain0}), a single $\sim$10{,}000-line function built around one giant
\texttt{switch} --- still exactly this shape today on stable Cbc branches. A first refactor revived the
class and moved \texttt{CbcMain1}'s body into it verbatim as \texttt{CbcSolver::run()} (\texttt{CbcMain0}%
/\texttt{CbcMain1} remain as thin wrappers). Further refactors (removing dead \texttt{\#ifndef JJF\_ONE} /
\texttt{\#if~0} blocks, splitting the branch-and-bound \texttt{case} into six cooperating private methods,
dropping the legacy \texttt{-miplib}/\texttt{-unitTest} harness) then extracted coherent phases into the
named methods below, reducing \texttt{run()} itself to a slim dispatcher. Local variables that needed to
survive across phases were promoted to \texttt{private} data members (see \S\ref{sec:state}). Most recently,
three of the finer-grained \textbf{actions} used inside that pipeline --- solving an LP relaxation, bound
propagation, and clique strengthening --- were promoted from private/inline/free-function code into public,
individually-callable, solver-parameterized methods (see \S\ref{sec:actions}), so they can be driven directly
on an arbitrary \texttt{OsiSolverInterface}/\texttt{OsiClpSolverInterface} instead of only on this
\texttt{CbcSolver}'s own \texttt{model\_.solver()} --- e.g.\ from the C interface.

\section{Individual solve actions}\label{sec:actions}
Three actions that used to be entangled --- inline, duplicated across call sites, or reachable only as a
private/free-function helper on \texttt{model\_.solver()} --- are now public \texttt{CbcSolver} methods that
each take an optional target solver parameter (\texttt{nullptr} defaults to \texttt{model\_.solver()}), so any
of them can be triggered directly on an externally-owned \texttt{OsiClpSolverInterface} while still honouring
every LP/bound-propagation/clique option configured on this \texttt{CbcSolver} (\texttt{CbcParameters},
\texttt{ClpParameters}):
\begin{itemize}[leftmargin=1.4em, itemsep=1pt]
  \item \textbf{\swatch{capi} \ghc{1217}{\texttt{applyLpMethod(OsiClpSolverInterface\,*targetSolver=nullptr,}}
    \texttt{int forcedMethod=-1)}} --- the unified root-LP-relaxation solver, and the \emph{only} place that
    actually solves it: bound propagation ($\to$ \texttt{strengthenBounds()}) $\to$ clique merging ``before''
    ($\to$ \texttt{strengthenCliques()}) $\to$ model-level LP settings (PSI positive-edge, objective scaling,
    vector mode) $\to$ LP racing (\texttt{-racingLP}) $\to$ full \texttt{ClpSolve} with every user-settable option
    (\texttt{-lpMethod} auto/dual/primal/barrier, presolve, crash/idiot/sprint, SLP, dualize, time limits).
    \texttt{forcedMethod} lets a caller pin the LP method (a \texttt{CbcParameters::LPMethod} value) for this call
    only, bypassing \texttt{-lpMethod=auto} and LP racing --- used by the \texttt{DUALSIMPLEX}/\texttt{PRIMALSIMPLEX}/
    \texttt{BARRIER} CLI commands, which used to hand-duplicate this entire option-setting sequence instead of
    calling it. Used internally by \ghc{5562}{\texttt{solveInitialLp()}} (root LP of the BAB pipeline) and, via
    \ghc{1580}{\texttt{runSolveContinuous()}}, by the \texttt{SOLVECONTINUOUS}/\texttt{DUALSIMPLEX}/\texttt{PRIMALSIMPLEX}/
    \texttt{BARRIER} actions; exposed publicly so the exact same, fully-configured solve (with any forced method)
    can be driven on any solver instance.
  \item \textbf{\swatch{capi} \ghc{1135}{\texttt{strengthenBounds(OsiSolverInterface\,*solver=nullptr)}}} ---
    runs the currently configured bound propagation (\texttt{-boundPropLevel}: singletons / fixpoint /
    MILP-based, up to \texttt{-boundPropMaxRounds} rounds via \texttt{CbcBoundPropagation}), falling back
    to legacy singleton-only tightening when propagation is off but \texttt{-singletonBounds} is on. Shared by
    \texttt{applyLpMethod()} (step 1) and the standalone \texttt{BOUNDPROP} action
    (\ghc{7084}{\texttt{runBoundPropagation()}}), which previously duplicated the same level-mapping and
    \texttt{CbcBoundPropagation::run()} call inline.
  \item \textbf{\swatch{capi} \ghc{1198}{\texttt{strengthenCliques(solver, mode, strengthenMode, \ldots)}}} ---
    (re)builds the conflict graph of the target solver and strengthens set-packing/partitioning cliques against
    it (extend/dominate), resolving the LP afterwards only in \texttt{"after"} mode. Thin \texttt{CbcSolver}-level
    wrapper filling in this solver's own model/handler/\texttt{mipStart\_} context around the lower-level free
    function that does the actual conflict-graph work; used by \texttt{applyLpMethod()}'s ``before'' step and by
    \ghc{7720}{\texttt{babPostPreprocessCleanup()}}'s ``after'' step, replacing what used to be two independent
    call sites each re-deriving the same handler/model/mipStart arguments.
\end{itemize}
As part of exposing these, a dead-code duplicate was removed from \ghc{5562}{\texttt{solveInitialLp()}}: a
second clique-strengthening pass and a second \texttt{model\_.initialSolve()} call, both gated on
\texttt{lpMethodResult > 0} --- a condition that can never hold, since \texttt{applyLpMethod()} only ever
returns \texttt{-1} or \texttt{0} and already performs both the clique pass and the LP solve internally.

\section{The branch-and-bound pipeline}\label{sec:pipeline}
\ghc{10320}{\texttt{run()}} dispatches on the current \texttt{CbcParam} command. Besides simple one-shot actions
(\S\ref{sec:other}), the \textbf{\texttt{BAB}} command drives the solver's core pipeline, implemented as six
cooperating private methods called in sequence (see the full diagram on the next page):
\begin{enumerate}[leftmargin=1.6em, itemsep=1pt]
  \item \ghc{7141}{\texttt{babSetupAndRootLp()}} --- cutoff sign flip, legacy \texttt{OsiSolverLink} path,
    solves the root LP via \ghc{5562}{\texttt{solveInitialLp()}} $\to$ \ghc{1217}{\texttt{applyLpMethod()}}.
  \item \ghc{7482}{\texttt{babConfigureBabModel()}} --- (re)builds \texttt{babModel\_} from \texttt{model\_}, configures
    the conflict-graph branching ranker (\ghh{649}{\texttt{RankerConfig}}), tunes factorization frequency.
  \item \ghc{3600}{\texttt{preprocess()}} --- runs \texttt{CglPreProcess} when preprocessing is enabled.
  \item \ghc{7720}{\texttt{babPostPreprocessCleanup()}} --- cgraph/clique-strengthening cleanup (via
    \ghc{1198}{\texttt{strengthenCliques()}}), post-preprocess bound tightening.
  \item \ghc{7838}{\texttt{babConfigureSearchModel()}} --- knapsack expansion, cost-based priorities, and
    invokes \ghc{10294}{\texttt{configureHeuristics()}} / \ghc{10300}{\texttt{configureCutGenerators()}}.
  \item \ghc{8230}{\texttt{babExecuteSearchAndPostprocess()}} --- SOS/priority setup, the actual
    \texttt{babModel\_->branchAndBound()} call, search-statistics bookkeeping, and finally
    \ghc{4841}{\texttt{postprocess()}} to translate the solution back and report results.
\end{enumerate}
Each phase returns a status code consumed by \texttt{run()} to decide whether to continue, \texttt{break}
the \texttt{BAB} case, or \texttt{return} from \texttt{run()} outright --- preserving the exact control flow of the
original monolithic function.

\section{Other \texttt{run()} actions}\label{sec:other}
\begin{itemize}[leftmargin=1.4em, itemsep=1pt]
  \item \textbf{\swatch{cother} IMPORT:} private \ghc{3296}{\texttt{importModel(inputQueue,\ldots)}} reads an MPS/LP/GMPL file.
  \item \textbf{\swatch{cother} SOLVECONTINUOUS / DUALSIMPLEX / PRIMALSIMPLEX / BARRIER:} private
    \ghc{1580}{\texttt{runSolveContinuous(forcedMethod,\ldots)}} sets up the shared LP progress handler, calls
    \ghc{1217}{\texttt{applyLpMethod()}} (forcing dual/primal/barrier for the latter three commands), maps the
    resulting Clp status onto \texttt{model\_}/\texttt{babModel\_}, and populates the AMPL info buffer. These four
    commands used to each keep an independent $\sim$200--450-line copy of this sequence; the CLP-method commands
    additionally hand-duplicated \texttt{applyLpMethod()}'s entire \texttt{ClpSolve} option-setting logic.
  \item \textbf{\swatch{cother} BOUNDPROP:} \ghc{7084}{\texttt{runBoundPropagation()}} runs standalone bound propagation
    (thin CLI wrapper around \ghc{1135}{\texttt{strengthenBounds()}}).
  \item \textbf{\swatch{cother} CHECKSOLUTION:} \ghc{7105}{\texttt{runCheckSolution()}} writes a solution-validation report.
  \item \textbf{\swatch{cother} WRITESOL / PRINTSOL / \ldots:} \ghc{5930}{\texttt{writeSolution()}} writes solutions in various formats.
  \item \textbf{\swatch{cutil} Bookkeeping:} \ghc{3001}{\texttt{printParamChanges()}} prints a parameter-change
    banner at the top of the \texttt{BAB} case; \ghc{2857}{\texttt{resetRunState()}} is declared/defined but
    currently \emph{never called} (orphaned --- dashed outline in the diagram).
\end{itemize}

\section{State organization}\label{sec:state}
\ghh{90}{Private data} falls into two groups. \textbf{Core state} (\ghh{343}{\texttt{model\_}}, \texttt{babModel\_},
\texttt{parameters\_}, \texttt{cutGenerator\_}, \texttt{userFunction\_}, \ldots) existed in the original class.
\textbf{Cross-phase state} (\ghh{373}{lines 373--573}) --- preprocessing (\texttt{process\_}, \texttt{saveSolver\_}),
solve-control flags, LP/barrier options, cut-generator modes, branching input (priorities/SOS/pseudo-costs),
MIP start, knapsack-expansion buffers, debug, lot-sizing, and timing/statistics --- used to be \emph{local
variables} inside the monolithic \texttt{run()}. Promoting them to member fields is what let \texttt{run()}
be split into the cooperating methods of \S\ref{sec:pipeline}: each extracted method reads/writes the
subset of this state it needs directly, instead of receiving dozens of by-reference parameters.
